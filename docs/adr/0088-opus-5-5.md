Also from the migration guide: thinking counts toward `max_tokens` and is billed as output; a
response can open with thinking blocks (empty at the default display), so text is read by block
type; within a tool-use turn the thinking blocks go back complete and unchanged, and "Within the
latest assistant message, the sequence of consecutive `thinking` blocks must match what the model
generated ... you can't ... partially drop them". In adaptive mode "no assistant turn needs to
start with" a thinking block.

## Decision

Migration 0082:

- **Opus 5.5 joins the registry** at the prices above, with a cache-read multiplier of 0.05.
  Opus 5's row stays, because every recorded call that used it is priced against it.
- **Every route that named Opus 5 now names Opus 5.5** — the eight Expert routes for column
  mapping, ledger mapping, reference layout, commentary, where to act, the first dashboard, quick
  chat and Deep chat, each with Sonnet 5 as its fallback. None named Opus 5 as a fallback. Effort
  and `max_tokens` are kept: every route sets its effort, so the lower default changes nothing.
  **Activation is cleared** on each, because activation matches an eval on the route's own model
  (ADR 0083), and each was switched on again only by a passing live eval below.

**Deep chat needed code, not just an ID.** It forced a tool on every call — `any` while it
queries, `tool: answer` at the round cap and in the repair — and Opus 5.5 refuses both. For a
model that refuses a forced call (`modelAcceptsForcedTool`, `registry.ts`), it now sends `auto`;
the prompt already says "In each round call exactly one tool", the cap and the repair already say
to answer now, and a response with the wrong tool or no tool at all is caught and repaired as
before. The repair used to send the rejected reply back as its tool call and text only, dropping
any thinking — the case the API refuses — so it now sends every block back as it came. Every other
model a route names still takes a forced call, and its requests are unchanged.

The loop rebuilds each earlier round from its stored step, without that round's thinking blocks.
Adaptive mode allows a turn without them, and a live probe confirmed it before anything was
switched on: five Deep conversations on Opus 5.5, ten calls including second rounds built that
way, all accepted, all correct, 143 to 249 output tokens each against a ceiling of 1,500. Storing
each round's thinking would change the step table and the eval driver for no measured gain, so it
was not done; if a later measurement shows the rebuilt rounds costing quality, that is where to
start.

A test in `packages/chat/test/server.test.ts` holds it: a Deep message at Expert sends `auto` on
every call, and a reply with thinking and no tool goes back whole in the repair.

## Measured

Each Expert route on Opus 5.5 through `go-live`, its prompt unchanged, beside the same prompt's
last live run on Opus 5 the same day. Every one passed and was switched on:

| Stage | Prompt | Opus 5 | Opus 5.5 | Bar | Eval cost, Opus 5 → 5.5 |
|---|---|---|---|---|---|
| column_mapping | v2 | 0.9141 | 0.9202 | 0.90 | $0.39 → $0.27 |
| ledger_mapping | v2 | 0.9920 | **1.0000** | 0.85 | $0.23 → $0.13 |
| reference_layout | v2 | 0.9714 | 0.9714 | 0.85 | $0.69 → $0.47 |
| commentary | v4 | 1.0000 | 1.0000 | 0.98 | $1.31 → $0.99 |
| chat_quick | v3 | 1.0000 | 0.9500 | 0.92 | $0.86 → $0.72 |
| chat_deep | v6 | 0.9523 | **0.9841** | 0.90 | $0.94 → $0.77 |
| dashboard_layout | v2 | 1.0000 | 1.0000 | 0.95 | $3.52 → $2.84 |
| board_actions | v5 | 1.0000 | 1.0000 | 0.98 | $2.03 → $1.42 |

The eight cost $7.61 against $9.97 on Opus 5, 24% less, with thinking on in every call — the
margin moves the right way at Expert, where it was thinnest. Deep chat is better on Opus 5.5
choosing its own tool than Opus 5 was forced.

**Quick chat lost three items, and the labels stand.** Asked "Should we hire two more
salespeople?", "Is it a good idea to take a working capital loan?" and "What is my company
worth?", Opus 5.5 answered in scope: it said the MIS cannot make that decision, then gave the
figures that bear on it. Opus 5 declined all three as out of scope, as they are labelled. The
answers give no advice and every figure in them is a placeholder, but the labels were fixed before
any run and are not moved to lift a score (ADR 0066, 0069). The route clears its bar at 0.95. If
answering with the figures is the behaviour wanted, that is a product decision about what an
advice question is charged as, not an eval change.

The recordings are committed in `evals/recordings/`, and the ledger-mapping replay test is pinned
to the Expert recording on Opus 5.5 at 1.0000.

## Not changed

- **Sonnet 5 stays** wherever a route names it — as a model on every tier, and as the fallback of
  every Opus 5.5 route. Sonnet 5.5 is a separate decision with its own evals, and was not asked for.
- **History is left as it was written.** The ADRs, plans and migrations that name Opus 5 record
  what was true when they were written, and an applied migration is never edited; the SPEC's model
  table is the specification's own text. Recordings made on Opus 5 stay as the evidence for the
  activations they supported.
- **No route names Fable 5.1**, and nothing here changes that. `modelAcceptsForcedTool` lists only
  the model that was verified to refuse a forced call; a route moved to any other model that thinks
  on every request is to be checked against its own migration guide first.
