# 0083 — Haiku 5.5 in place of Haiku 4.5

- **Status:** accepted
- **Date:** 2026-10-08
- **Decided by:** the product owner, who asked to "change the model haiku 4.5 to haiku 5.5".
- **Builds on:** [0019](0019-ai-layer.md), [0066](0066-a-limit-the-model-is-never-told.md),
  [0077](0077-deep-chat-measured.md).

## Verified

Every fact below was read on 2026-10-08 from the official documentation (SPEC §0.4):

- Models overview — https://platform.claude.com/docs/en/about-claude/models/overview
- Haiku 5.5 — https://platform.claude.com/docs/en/models/haiku-5-5/overview
- Migration guide — https://platform.claude.com/docs/en/models/haiku-5-5/migration-guide
- Pricing — https://platform.claude.com/docs/en/about-claude/pricing
- Effort — https://platform.claude.com/docs/en/build-with-claude/effort

| | Haiku 4.5 | Haiku 5.5 |
|---|---|---|
| Model ID | `claude-haiku-4-5-20251001` | `claude-haiku-5-5` (fixed, no alias), released 2026-10-07 |
| Input / output per MTok | $1 / $5 | $0.10 / $0.50 up to 100,000 prompt tokens; $0.50 / $2.50 over |
| Cache write 5 m / 1 h, read | $1.25 / $2, $0.10 | $0.125 / $0.20, $0.01 — each five times over 100,000 |
| Thinking | none unless asked for | adaptive, **on by default**, steered by effort (default `medium`) |
| Effort | not accepted | `low` to `max`; `low` recommended for chat and simple high-volume work |
| Tokenizer | older | about 30% more tokens for the same text |

Also from the migration guide: thinking counts toward `max_tokens`; a response can open with a
thinking block (empty text, signature only); `temperature`, `top_p` and `top_k` must be omitted;
assistant prefill is refused; `stop_reason: "refusal"` must be handled. The orchestrator already
reads the answer by block type, handles a refusal, and sends no sampling parameters or prefill,
so none of those needed a code change — a test now pins the thinking-block case.

## Decision

Migration 0075:

- **The registry carries a price band.** Haiku 5.5 is the first model priced by prompt length,
  and every one of its prices is exactly five times as much past 100,000 prompt tokens, so
  `model_registry` gains `long_prompt_threshold_tokens` and `long_prompt_price_multiplier`,
  null for a single-price model. `costMicroUsd` counts the prompt as uncached input plus cache
  writes plus cache reads — the documentation does not say which of them the threshold counts,
  and counting all of them can only ever price a call at the higher band, never understate it.
  The pre-call projection goes through the same function, so the runtime cap sees the band too.
  The admin console's price publish carries the band into each new version.
- **Every route that named Haiku 4.5 now names Haiku 5.5** — nine as the model, ten as the
  fallback. Where it is the model: effort `low` (the documented replacement for a route that ran
  without thinking), `max_tokens` doubled (thinking and the newer tokenizer both spend the old
  ceiling; a ceiling costs nothing until used), and **activation cleared**, because activation
  matches an eval on the model in the route and none has run on Haiku 5.5. Where it is only the
  fallback, it is swapped in place and the route keeps its activation, as it always has.
- **The estimator's characters per token for sheet recognition** falls from 2.7 to 2.1: its 2.76
  was measured mostly on Haiku 4.5's older tokenizer, and 2.76 / 1.30 rounds down to 2.1.

Haiku 4.5's registry row stays: every recorded call that used it is priced against it.

## What this means until a live eval runs

These nine routes refuse with `stage_not_activated` until `go-live` (or the admin console's
Activate) records a passing live eval on Haiku 5.5:

| Tier | Stages |
|---|---|
| Efficient | sheet recognition, column mapping, quick chat, where to act, thread summary |
| Professional | sheet recognition, **dashboard changes by chat**, thread summary |
| Expert | thread summary |

In production nothing changes: every route starts off and `go-live` evaluates whatever routing
it finds, so it will measure Haiku 5.5 directly. Locally, those stages stop until the evals are
run with a funded key — at Haiku 5.5's prices the nine evals cost cents. Sheet recognition is
called only when a run finds no balances, and an AI stage that cannot run never fails a run.

## Margin

Up to 100,000 prompt tokens Haiku 5.5 costs a tenth of Haiku 4.5 per token, against roughly 30%
more tokens for the same text and whatever thinking `low` still does. Every stage here sends far
less than 100,000 tokens. The measured ratio replaces this estimate once the first live evals are
recorded (R-09, R-28), and those recordings should also re-measure the estimator (R-30).

## Measured, 2026-10-09

The owner funded the key, and the ten routes that were off locally — the nine above and Expert
Deep (R-44) — were run live through `evals` and switched on through `activate`, the same gate as
the console's button. All ten passed; the recordings are committed in `evals/recordings/`
(Haiku 4.5's are in history at `d9e38c2`, and no route reads them any more). Total spend $1.09.

| Route | Haiku 4.5 | Haiku 5.5 | Run cost, 4.5 → 5.5 | Threshold |
|---|---|---|---|---|
| Sheet recognition, Efficient | 0.966 | 1.000 | $0.135 → $0.006 | 0.95 |
| Sheet recognition, Professional | 1.000 | 1.000 | $0.135 → $0.006 | 0.95 |
| Column mapping, Efficient | 0.920 | 0.902 | $0.111 → $0.009 | 0.90 |
| Quick chat, Efficient | 0.964 | 0.982 | $0.152 → $0.015 | 0.92 |
| Chat edits, Professional | 0.980 | 0.961 | $0.194 → $0.014 | 0.95 |
| Where to act, Efficient | 1.000 | 0.981 | $0.181 → $0.017 | 0.98 |
| Thread summary, all three tiers | 1.000 | 0.981 / 1.000 / 0.981 | $0.057 → $0.006 | 0.90 |
| Deep, Expert (Opus 5) | — | 0.952 (60 of 63) | $1.006 | 0.90 |

Every Haiku 5.5 run cost a tenth or less of the same run on Haiku 4.5, including its repair rounds.
No call came near its output ceiling (the largest used 1,630 of 12,000), so the doubled
`max_tokens` is room, not a limit, and R-09 may lower it.

What the misses were, read from the recordings at no cost:

- **Haiku 5.5 types a figure on a quarter of its first answers** in where to act (13 of 54) and
  chat edits (12 of 51) — "rose about 13.6%", "fell by the same 20 percent". The placeholder check
  refuses every one and the single repair round fixes it, so no model-typed number reached an
  answer (locked decision 7 held), at the cost of a second call. A prompt version that names the
  habit would remove the second call; it needs its own eval.
- **Quick chat's injection item** was declined in so many words ("I am declining that
  instruction") but labelled in scope rather than out of scope. Not a breach.
- **Deep's three Expert misses** were questions the books cannot answer, which Opus answered by
  saying the data does not exist instead of declining the question. Nothing was invented. The
  labels stand: relabelling to lift a score is choosing the answer first (ADR 0066, 0069).

## Not changed

Sonnet 5.5 and Opus 5.5 are also current and the routes still name Sonnet 5 and Opus 5. That is a
separate decision, with its own evals, and was not asked for.
