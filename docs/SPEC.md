## 1. Product summary

[PRODUCT_NAME] turns business data exports into a management-ready MIS.

**The core flow:**
1. The user uploads Excel workbooks, CSVs and Tally exports: trial balance, P&L, balance sheet, day book, sales and purchase registers, outstandings, stock and payroll.
2. They choose an MIS template or upload their existing MIS to have it recreated.
3. They confirm how their ledgers map to MIS heads.
4. They receive a validated Excel MIS with live formulas, an interactive dashboard, and management commentary.

**Monthly refresh:** next month, the system recognises the company's saved MIS blueprint, so a refresh takes minutes and usually needs little or no AI work.

**Pricing:** customers prepay credits and every action costs credits.

**Core technical principles:**
- Raw files are processed in the user's browser.
- All numbers are computed deterministically.
- Claude (Anthropic API) is used only for understanding structure (classification, mapping, reference-layout extraction) and for language (commentary, chat answers).
- Claude never produces a number that appears in any output.

**Customers:**
- **Primary:** Chartered Accountant firms producing MIS for many SME clients.
- **Secondary:** SME finance teams.

**Business priority:** gross margin is the single most important property of this product. Every design choice that affects cost or pricing must protect it.

## 2. Locked decisions

1. **Standalone product.** Own brand, infrastructure, Anthropic account, payment gateway account and database. No shared code or identity with any other product.
2. **One login per account.**
   - No team members, invitations, roles, organisations, sub-users or shared access of any kind.
   - One active session per account: a new login terminates the previous session.
3. **Nothing is free.**
   - No free tier, free trial, free generation, free sample on the user's data, or free preview of analysis.
   - Before a paid action, the UI may show only file names, file sizes, sheet counts and row counts (needed for price estimation). Sheet recognition, mapping results, data-quality findings and every output are shown only inside a paid action.
   - Account creation, buying credits, viewing the price book, reading help docs and viewing public marketing samples built on fictional data are the only uncharged activities.
4. **Prepaid credits only.**
   - 1 credit = ₹1, excluding GST.
   - Credits must be purchased before use.
   - No postpaid usage, no negative balances, no credit lines.
5. **Fixed credit price per action from a configurable price book.** Users never see tokens, model names or AI cost. Tier multipliers apply.
6. **Margin guardrail.**
   - Every action has `max_ai_cost_ratio` (default 0.20): AI cost for the action must not exceed 20% of its credit price.
   - If a job's estimate exceeds this before running, the user must accept a quote first.
   - If a job hits the cap while running, it pauses; it never silently overspends.
7. **Claude never outputs numbers.** Every figure in every output, commentary and chat answer is computed by the deterministic engine and inserted through placeholders.
8. **Raw files never leave the browser by default.**
   - Only these are sent to our server: structural profiles, capped redacted samples, and aggregates.
   - Anthropic receives only what the server sends for a specific action.
9. **Anthropic API key is server-side only.**
   - The server exposes action-specific endpoints only. There is never a generic prompt passthrough.
   - The browser cannot choose prompts, models or token limits.
10. **Intelligence tiers, not model names.** Tiers are Efficient, Professional and Expert. An Expert+ tier using the highest model exists only as an admin-issued quote and is disabled by default.
11. **Chat with the MIS costs credits per message.**
12. **Recurring costs.** Every monthly refresh consumes credits. Each active company also incurs a monthly company memory fee.
13. **Desktop only.** Latest Chrome, Edge and Firefox. Mobile browsers see a message that the app requires a desktop.
14. **Indian context.**
    - INR, with GST on credit purchases
    - Financial year April to March by default (configurable per company)
    - Lakhs/crores number formatting (with absolute and millions options)
    - Timestamps stored in UTC, displayed in IST
    - Dates parsed as day-first, never month-first

## 4. Engineering conventions

- **Language and validation:** TypeScript `strict` everywhere. Zod schemas at every boundary: HTTP, database JSON columns, AI inputs and outputs, file parsing results, config.
- **Header-based parsing only.** Never rely on column positions.
- **Time:** stored in UTC, displayed in IST.
- **Money and quantities:**
  - INR stored as integer paise
  - Credits stored as integers
  - AI cost stored as integer micro-USD, plus the INR equivalent at the FX rate in effect
  - Never use JavaScript floating point for money
  - In DuckDB, use `DECIMAL(38,4)` or integer paise
- **Idempotency** on every mutating operation: API endpoints take an `Idempotency-Key`, webhooks are de-duplicated by event ID, and file imports are keyed by content fingerprint.
- **Soft-delete everywhere** (`deleted_at`), plus scheduled purge jobs. Purge of encrypted company data uses crypto-shredding: destroy the company's data key.
- **Append-only, hash-chained audit log** (`prev_hash`, `hash`) for:
  - auth events
  - wallet mutations
  - pricing and config changes
  - admin actions
  - deletions
  - consent records

  The credit ledger is also hash-chained.
- **Environment:** variables validated at boot with Zod. The app refuses to start on invalid config.
- **Business config:** lives in the database with versioning and `effective_from`. Every config change is written to the audit log.
- **Tests:** all business rules have unit tests; money and ledger logic has property tests.

## 7. System architecture and trust boundaries

The system has three zones.

**Zone A: Browser.** Holds the raw data; treated as an untrusted client.
- Reads files, parses, profiles, redacts, runs DuckDB computation, runs validation, and renders Excel and dashboards.
- Holds the redaction token map, which never leaves the browser.
- Sends to the server only:
  - redacted structural profiles
  - capped redacted samples
  - aggregates (ledger × period balances, metric store)
  - chat query results that pass the row cap and redaction

**Zone B: Our server (Next.js route handlers + worker).** Trusted.
- Owns auth, wallet, pricing, quotes, job state, the AI orchestrator, persistence of blueprints and snapshots, billing, and notifications.
- Builds every prompt itself from validated, size-capped payloads.
- Computes charges only from Anthropic usage data it receives directly. It never uses cost or usage figures reported by the browser.

**Zone C: Anthropic API.** Vendor.
- Receives only what an action-specific server function sends.

**Enforced rules:**
- No endpoint accepts free-text prompts to forward to Claude. The only free-text AI inputs are chat messages, and they are wrapped in the chat system prompt with scope restrictions.
- Every AI endpoint has a Zod schema and a maximum payload size per action. Oversize payloads are rejected with a clear error.
- Model, effort and `max_tokens` are chosen server-side from the tier routing config.
- Metrics computed in the browser are trusted only as the user's own data. They only affect that account's outputs.

## 10. Storage, encryption, retention and deletion

**What is stored**

| Data | Stored? | Where | Notes |
|---|---|---|---|
| Account, security, consents | Yes | Postgres | Personal data under DPDP |
| Credit ledger, lots, purchases, invoices | Yes | Postgres | Financial records; retained per statutory requirement (config, default 8 years), even after account deletion, with personal fields minimised |
| Company blueprints (template, recipe, mappings, dashboard spec) | Yes, encrypted | Postgres | This is the "memory" |
| Snapshots (ledger × period balances, metric store) | Yes, encrypted | Postgres | Enables comparatives, continuity checks, quick chat |
| Generated Excel outputs | Yes, encrypted, retention (default 90 days) | Supabase Storage | Re-download; expiry purge job |
| AI job stage outputs | Yes, encrypted, retention (default 30 days) | Postgres | Retry reuse and debugging |
| Prompts and raw AI responses | Encrypted, retention (default 30 days), config switch to disable | Postgres | Never in plaintext logs |
| Raw uploaded files | Never (this build) | Browser memory / OPFS only | Cleared on logout, on "Clear session data", and on tab close where possible |
| Redaction token map | Not by default | Browser only; optional encrypted dictionary per company setting (Section 17) | Rehydrates names in UI |

**Encryption**
- Envelope encryption: each company has its own data encryption key (DEK), wrapped by the KMS master key. Account-level encrypted fields use the account DEK.
- Decrypt only in server code that needs the plaintext, and only for the owning account.
- Keep key rotation support: re-wrap DEKs when the master key rotates.

**Deletion**
- Company delete: soft-delete, then purge after the configured period (default 30 days) by destroying the company DEK (crypto-shred) and deleting its rows and files.
- Account delete: same approach for all companies and account data. Statutory billing records are retained with minimised personal fields.
- Data export (DPDP-aligned): JSON export of account profile, companies, blueprints (decrypted), snapshots (decrypted), invoices and ledger. Generated asynchronously and emailed as a time-limited download link.

## 11. Credit wallet and ledger

**Definitions**
- `balance_credits` = sum of `credits_remaining` across unexpired lots.
- `held_credits` = sum of active reservations.
- `available` = balance − held.

**Transactions.** All wallet operations run in one Postgres transaction that locks the account's `wallets` row with `SELECT ... FOR UPDATE`. Every operation writes `credit_ledger` entries with `balance_after`, `held_after` and the hash chain.

**Operations**
1. **Grant** (purchase, bonus, admin grant). Creates a lot:
   - `expires_at` = grant date + validity (config, default 12 months).
   - Pack bonus credits are a separate lot with the same expiry.
   - Increases balance.
2. **Reserve.** Requires `available ≥ amount`.
   - Creates a reservation with `expires_at`: real-time jobs default 2 hours; jobs awaiting mapping review default 72 hours; batch jobs default 26 hours.
   - Increases held.
   - Fails with `INSUFFICIENT_CREDITS` and returns the shortfall.
3. **Capture(amount ≤ reserved).**
   - Consumes lots FIFO by earliest `expires_at`.
   - Decreases balance and held.
   - Releases any remainder.
4. **Release.** Decreases held; the reservation becomes released.
5. **Expire lots.** Nightly worker job:
   - Sets remaining to 0 and writes an `expire` ledger entry.
   - If an expiring lot is needed to cover an active hold, the hold is re-covered by later lots. If later lots cannot cover it, the expiry still applies and the job's capture is limited to available credits; the job fails with `platform_fault` only if the shortfall is caused by our timing.
   - Notices are sent 30 days and 7 days before expiry.
6. **Reservation sweeper** (every 5 minutes):
   - Expired reservations with no heartbeat in the last 10 minutes are released and their job moves to `expired`.
   - Jobs send heartbeats while running.
7. **Admin adjust.** Positive adjustments create an `admin_grant` lot. Negative adjustments consume lots FIFO. A reason is required and audit-logged.

**Policies (defaults, in config)**
- Credits are non-refundable, non-transferable and cannot be withdrawn as cash. This keeps the wallet a closed-system instrument usable only for our own services.
- No cash refunds except where legally required. An admin-only refund flow exists for exceptional cases.

**Required tests**
- **Property:** ledger replay reproduces `wallets` state exactly.
- **Property:** balance and held never go negative under any operation sequence.
- **Concurrency:** 50 parallel reservations against a balance that fits 10 result in exactly 10 successes and no overdraft.
- **Idempotency:** the same idempotency key applied twice produces one effect.
- **Time travel:** lot expiry, reservation expiry and FIFO order.

## 12. Pricing engine, price book and quotes

**Price formula**

```
price(action, tier, delivery) =
  round_to_config( base_credits[action]
                   × tier_multiplier[action][tier]
                   + (delivery == instant ? instant_surcharge[action] : 0) )
```

## 15. Browser ingestion (`packages/ingest`)

**Accepted inputs**
- `.xlsx`, `.xlsm` (macros never executed), `.xls`, `.csv`
- Limits (config): 100 MB per file, 250 MB per session, 30 files per job
- Zip-bomb protection: cap the uncompressed size and entry count before parsing.

**All parsing runs in Web Workers.** The main thread never blocks. Show progress per file.

**Excel reading (SheetJS)**
- Read cached cell values (never evaluate formulas), plus formatted text for type inference.
- Detect merged cells, hidden sheets and hidden rows. Hidden items are flagged in the profile, not dropped silently.

**CSV**
- Detect delimiter and encoding.
- Stream large CSVs into DuckDB via file registration; do not materialise them as JS objects.

**Loading into DuckDB**
- Each sheet becomes one DuckDB table with sanitised names.
- Every row gets provenance columns: `_file_id`, `_sheet`, `_source_row` (1-based as seen in Excel).
- Original header text is kept in a header map.

**Header detection**
- Score candidate rows by text density, uniqueness, type contrast with the rows below, and known header vocabulary.
- Support multi-row headers by concatenating levels.
- Title rows above headers (company name, period text) become sheet metadata.

**Type inference**
- **Dates:** day-first always. Formats: `1-Apr-25`, `01-04-2025`, `01/04/2025`, Excel serials. Never interpret as month-first.
- **Amounts:**
  - Indian grouping (`1,00,000.00`) and international grouping
  - Parentheses mean negative
  - Trailing `Dr`/`Cr`: record the sign convention explicitly in the profile, never guess silently
  - Separate Debit and Credit columns
- **Percentages, text and codes:** GSTIN, PAN and similar are detected as identifier types.

**Fingerprints**
- SHA-256 of file bytes.
- A per-sheet header signature (normalised header names + inferred types + detected report type) used to match blueprints next month.

**Session hygiene**
- Raw data lives in DuckDB memory and OPFS temp only.
- Clear it on logout, on "Clear session data", and on new-session start. Attempt cleanup on tab close.

**Before payment**, the UI shows only file name, size, sheet count and row counts.
